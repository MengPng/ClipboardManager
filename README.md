# 本地剪切板管理工具

一款面向 Windows 的 Local-first（本地优先）剪切板历史工具。它首先提供稳定、快速、隐私友好的本地使用体验，并从架构上为账号系统、个人多设备云同步和团队共享剪切板预留扩展能力。

## 0.8.5 桌面宠物「夹夹」（当前开发版本，未正式发布）

当前版本号为 **0.8.5**（`0.8.5-desktop-pet`），数据库保持 schema 7。0.8.0–0.8.5 的变更均记录在 [CHANGELOG](CHANGELOG.md) 的「Unreleased」中；正式发布版仍为 0.7.9。

0.8.5 将宠物重绘为原创的"夹夹"（带折角与横格线的纸页，头顶赤陶夹子），新增按住拖动时的"被拎起"状态，并修复非 100% DPI 下拖拽错位、可拖出屏幕、隐藏后动画仍运行的问题。**0.8.5 已编译、通过自动化测试并完成打包**（`artifacts/release/0.8.5/`）。以下为 0.8.4 起的桌面宠物能力：

- **收起即宠物**：收起后主窗口隐藏，一只 56×40 的透明像素宠物（无背景、无边框）悬浮桌面。单击展开剪切板；按住约 0.3 秒后可拖到任意位置；Esc 隐藏宠物与面板。
- **状态即反馈**：监听中眨眼呼吸，暂停时趴睡，捕获到新内容时跳一下。展开后宠物回到页脚，仅作展示。
- **自动展开**：呼出快捷键、托盘和单实例唤醒在收起态下都会展开主面板；在设置中关闭宠物后，收起回退为紧凑标题条。
- **吸附保持**：收起不会拆掉聊天窗吸附，宠物跟随目标窗口移动，展开后交还主面板。
- **修复**：收起后宠物尺寸错误、连续点击卡死、画面空白或进程退出；连续使用文件历史时 `Clipboard.Flush()` 竞争导致的 `0x800401D0`（改为直接写入标准 `CF_HDROP`，保留 OLE 兜底）。
- **依赖**：保持 .NET 8 LTS，Microsoft.Data.Sqlite 8.0.32、Npgsql 8.0.9、Markdig 1.4.2、Serilog.Sinks.File 7.0.0。

构建产物位于 `artifacts/release/0.8.5/`（单文件 EXE、便携 ZIP、MSI 与 `SHA256SUMS.txt`），均为 Windows x64 自包含、未签名；重新构建：`.\scripts\build-release.ps1 -Version 0.8.5`。真实桌面点验、多显示器与不同 DPI、长期运行仍待验收。

## 划词与 AI（开发版本）

在“设置 → 划词与 AI”中独立开启快捷键和自动浮窗，默认均关闭。快捷键默认为 `Ctrl+Shift+G`，不占用主面板的 `Alt+V`；自动浮窗在鼠标拖选或双击后尝试读取选区。浮窗固定为 34px 高的无标题操作条，只显示“翻译 / 摘要 / 解释”等已配置动作，不显示选中文本、关闭键或其他说明。保存后立即应用，快捷键冲突会提示。

划词配置现放在主窗口顶部的“划词”页签，位于“计算”右侧；原通用“设置”窗口不再重复放置该入口。

默认使用 DeepSeek 的 `https://api.deepseek.com` 和 `deepseek-flash`（2026-10-21 核对官方文档），也可选择 OpenAI 兼容接口，或“本地 AI 网关（OpenAI 兼容）”。本地网关允许 `http://127.0.0.1:端口/v1`、`http://localhost:端口/v1` 或 `http://[::1]:端口/v1`；远端接口仍强制 HTTPS。模型名称和 Base URL 可自行填写，地址不含 `/chat/completions`；默认本机地址和模型只是示例，须替换为实际网关配置。本地免鉴权网关可不填密钥；已保存密钥可通过移除操作清除。密钥按服务商及地址隔离，保存在 Windows 凭据管理器，不进入设置文件、备份或日志；更换接口地址须另行配置密钥。

支持多条提示词的新建、改名、编辑、删除和排序；`{text}` 替换为原始选中文字。点击“翻译”等操作立即发送一次请求，结果窗口仅显示模型返回内容和状态，不展示原文、完整提示词或二次确认按钮。仅选中文字或打开操作条不会联网。支持取消、失败后手动重试及复制结果；关闭窗口取消正在进行的请求，不自动替换原文、不自动保存结果、不进入同步队列。

结果框和窗口高度随内容自适应，超出当前屏幕可用高度时滚动展示；Markdown 标题、加粗、斜体和代码围栏等统一转换为普通文本后显示，复制结果保持相同文本。正文中的有效字符（例如 `C#` 或乘法表达式）保留。

划词操作条显示后，点击条外任意空白位置即可取消并收起；点击“翻译”等按钮不会被此规则误取消，快捷键和自动浮条两种入口都适用。

Magpie 本机网关示例为 `http://127.0.0.1:3425/v1`，模型示例为 `qoder/dfmodel`，具体以网关接入页为准。旧版示例中的 8317 不是自动发现的端口；连接失败时先核对网关界面地址。

采集使用短暂 `Ctrl+C`，预先备份剪切板并在完成后恢复；临时副本与恢复事件按具体序列号从本工具历史监听中隔离。其他应用中途复制时保留最新内容，不盲目覆盖。暂停监听和排除应用在读取前生效；无法安全备份的特殊格式、超过 64 MiB 的内存格式载荷会停止采集。选区最多 32000 个 UTF-16 字符，完整提示词最多 100000 字符。图片保留 DIB 像素，Windows 负责重新生成对应位图格式。

全局划词不是所有控件都支持的系统标准：复制受限、管理员窗口、特殊/延迟剪切板提供方及把 Ctrl+C 定义为其他操作的应用需逐个验证。自动浮窗关闭时仍可独立使用快捷键。相同进程内用户并发复制与程序复制无法仅凭 Win32 来源完全区分；不承诺此类竞争下的选区识别。

Windows 真实探针：`dotnet run --project tools/ClipboardManager.DesktopProbe -- --selection`。探针使用临时数据库和独立测试进程，不发送真实模型请求；覆盖实际选区读取、原剪切板恢复、历史隔离、隐私排除、快捷键与浮窗。详见 [架构决策](docs/adr/0004-selection-ai.md)。本功能尚未封装为正式发布版本，真实密钥联调、多显示器与不同 DPI 仍需验收。

## 下载与安装

正式版本通过 GitHub Releases 分发：

- `ClipboardManager-<version>-win-x64.exe`：推荐下载。单个文件即可运行，已内置备份恢复组件，无需安装 .NET 或下载其他文件。
- `ClipboardManager-<version>-win-x64-portable.zip`：免安装便携包，解压后运行 `ClipboardManager.exe`。
- `SHA256SUMS.txt`：发布文件完整性校验。

两个版本均为 Windows x64 自包含发布，目标电脑无需预装 .NET 运行环境。MSI 暂不进入正式 Release，待安装兼容性验收完成后再恢复分发。当前产物尚未进行商业代码签名，Windows 可能显示“未知发布者”。

> 当前状态：`0.7.6` 提供本地“个人待办”，数据保存在 Local Workspace 的 SQLite schema 7 中，不进入云同步或团队空间。待办支持创建、完成/恢复、标签多选、筛选和统计；右键菜单的复制待办或列表中的 Ctrl+C 可复制正文，输入框内保留原生复制行为；标签完全由用户自定义，新 Workspace 不自动创建标签，删除标签只解除关联而不删除待办。schema 6 升级到 7 时会移除旧版系统预设标签及其关联，同时保留待办和自定义标签。完整备份与恢复包含待办、标签及关联关系。当前发布仍为 Windows x64 自包含且未签名；多显示器/不同 DPI、长期运行和特殊高权限目标仍需持续实机验收。

### 0.4.5 启动可用性修复

- 单实例唤出失败不再静默退出。若互斥体被一个不响应命名管道的进程占用，第二次启动会在重试 5 秒后弹出提示，引导用户结束残留进程，而不是让人以为"EXE 打不开"。
- SQLite 连接改用私有缓存并设置 15 秒命令超时。共享缓存会引入 busy_timeout 无法解除的进程内表级锁，读写连接可能相互死锁并把启动卡在建窗口之前。
- 接入 Serilog 文件日志，写入此前一直为空的 `%LOCALAPPDATA%\ClipboardManager\logs`。按天滚动、单文件上限 8 MB、保留 7 份。启动的每一步在执行前先记录，日志最后一行即为卡住的步骤；启动异常改为先 `LogCritical` 再弹窗，不再只存在于对话框里。此前只有 `AddConsole()`，而从资源管理器启动的 WinExe 没有控制台，所有诊断信息都被丢弃。
- 统一两条发布路径。单文件选项（`IncludeNativeLibrariesForSelfExtract`、`EnableCompressionInSingleFile`）下沉到 csproj，`build-msi.ps1` 与 `publish-single-exe.ps1` 不再各自重复。此前 MSI 脚本漏了压缩开关，产出 159 MB 的 EXE，与便携版 70 MB 并非同一份二进制。
- 已验证：占住互斥体且不开管道时弹出「无法唤出已运行的实例」；健康实例的第二次启动仍静默退出、不误报；日志文件实际生成并按序记录 6 个启动里程碑；两条发布路径产物 SHA-256 完全一致（70.53 MB）；51 项单元测试通过；重新发布的单文件 EXE 启动正常并显示主窗口。
- 未验证：原始卡死为偶发现象，本次未能复现，因此无法证明共享缓存就是其根因。该结论需等下一次卡死时用新增日志确认。

## 产品目标

工具需要解决以下核心问题：

- 自动保存复制过的文本、图片和文件列表。
- 使用全局快捷键快速呼出历史面板。
- 搜索、筛选、收藏、置顶和删除历史记录。
- 将历史内容重新写回系统剪切板，并可选自动粘贴。
- 数据默认只保存在本机，离线和未登录时完整可用。
- 后续可平滑接入账号、多设备同步和团队显式分享，而不重构本地捕获主链路。

## 产品原则

### 本地优先

- 本地剪切板功能不依赖账号、网络或云端服务。
- SQLite 是当前设备上的即时数据源。
- 网络故障不得阻塞剪切板捕获、搜索和重新使用。
- 云端能力是增量扩展，而不是本地功能的前置条件。

### 隐私默认

- 新捕获内容默认进入本机空间。
- 不自动上传剪切板历史。
- 不自动把个人内容发布到团队。
- 提供暂停监听、应用排除、自动清理和彻底清除本地数据能力。

### 显式团队分享

未来的团队共享不是“把整个个人剪切板同步给团队”。用户需要显式选择记录并分享到指定团队空间。分享会创建独立团队副本，本地原记录仍保持原有归属。

## 首期范围

首期面向 Windows，计划实现：

- 文本、图片和文件列表捕获。
- 剪切板历史持久化。
- 全局快捷键显示/隐藏面板。
- 搜索和类型筛选。
- 收藏、置顶、删除和清空。
- 历史内容重新写回剪切板。
- 可选自动粘贴。
- 系统托盘、单实例、托盘一键重启和开机启动。
- 首次启动询问是否启用 24/48/72 小时自动完整备份；备份按“本机名-日期时间-剪切板备份”命名，同一自然日的新自动备份替换当天旧文件，设置页仍支持手动导出。
- 来源应用记录和应用排除。
- 图片缩略图、缓存上限和过期清理。
- 多显示器和 DPI 适配。

首期不会实现真实的账号服务、云端 API、跨设备同步或团队管理，但会建立必要的领域模型和抽象接口。

## 界面方向（0.7.x 历史设计记录）

以下为旧版界面说明。0.8.0 的实际结构与验收状态以本文顶部「0.8.0 青序全局结构」及其验收记录为准。

主窗口是一块半透明的浮动面板：无系统标题栏，圆角，背景由 Windows 11 DWM 亚克力材质透出，视觉层次参考 macOS 的 vibrancy——导航与文件夹栏保持通透，列表表面接近不透明以保证正文对比度。

```text
┌──────────────────────────────────────────────┐
│ 剪切板 · 本机        ● 监听  钉住 暂停 设置 ✕ │
├──────────┬───────────────────────────────────┤

├──────────────────────────────────────────────┤

│                                              │
├──────────────────────────────────────────────┤
│ 记录数量 / Workspace          快捷键提示      │
└──────────────────────────────────────────────┘
```

- 三个视图入口是顶部居中的胶囊分段控件，与筛选胶囊同一套视觉语言。
- 「个人配置」与「团队配置」共用同一套文件夹栏与内容栏控件，切换只改变目标 Workspace，不重建界面。「团队配置」顶部常驻提示说明它目前只保存在本机。
- 筛选项是可换行的胶囊按钮（`RadioButton` 分组），当前筛选是真实控件状态而非由代码设置字重。
- 钉住、暂停、设置和隐藏为图标按钮，各自带 `AutomationProperties.Name`，因为图标本身是私有区码位。
- 列表行高提供宽松与紧凑两档，由设置项 `CompactList` 持久化，切换后立即生效且不重建缩略图。

主题实现约定：

- 所有颜色、字体、圆角与行距集中在 [`Themes/Palette.xaml`](./src/ClipboardManager.Windows/Themes/Palette.xaml)，控件模板集中在 [`Themes/Controls.xaml`](./src/ClipboardManager.Windows/Themes/Controls.xaml)。两者按顺序合并进 `App.xaml`。
- 界面代码不得内联画刷。需要换主题或做暗色时只应改调色板，不应逐个控件修改。
- 亚克力只使用有文档的 `DwmSetWindowAttribute`；不支持时（Windows 10 或调用被拒）降级为不透明背景，不调用未公开的 `SetWindowCompositionAttribute`。

不同内容类型使用不同的记录预览：

- 文本：正文摘要、来源应用和时间。
- 图片：缩略图、尺寸、大小和来源。
- 文件：文件名、父目录、数量和有效状态。

计划的默认键盘操作：

| 快捷键 | 行为 |
|---|---|
| `Alt+V` | 显示或隐藏面板 |
| `Up` / `Down` | 切换记录 |
| `Enter` | 将选中内容写回剪切板 |
| `Ctrl+Enter` | 写回并尝试自动粘贴 |

| `Ctrl+D` | 历史视图：把选中记录快速存入「个人配置」的未分类 |

## Local-first 数据归属

所有剪切板记录都属于一个 Workspace：

| Workspace 类型 | 用途 | 首期状态 |
|---|---|---|
| `Local` | 本机剪切板历史，以及「个人配置」库 | 实现 |
| `Personal` | 个人云端、多设备同步 | 预留 |
| `Team` | 「团队配置」库，**目前仅本机**，无账号、无服务端、无同步；真正的团队共享仍是预留 | 部分实现 |

剪切板捕获永久锚定在 `Local`。界面切换到「团队配置」只改变配置库的查询目标，不会改变新复制内容的归属。详见 [`docs/adr/0002-team-config-local-only-workspace.md`](./docs/adr/0002-team-config-local-only-workspace.md)。

每条记录从一开始就具有：

- 跨设备唯一的 UUID。
- `workspace_id`。
- `device_id`。
- 创建、更新和软删除时间。
- 本地与远端版本字段。
- 同步状态。

这样后续启用多设备同步时，不需要重做主键、数据归属和删除模型。

## 核心模块

### Clipboard Capture

负责：

- 注册 Windows 剪切板更新监听。
- 读取文本、图片和文件格式。
- 有限重试被占用的剪切板。
- 获取来源进程。
- 避免工具自身写回产生捕获循环。
- 将系统格式转换为领域模型。

### Application

负责：

- 捕获记录入库。
- 搜索和筛选。
- 收藏、置顶和删除。
- 重新使用历史内容。
- Workspace 上下文。
- 清理策略。
- 未来同步编排。

### Local Storage

负责：

- SQLite 仓储。
- 数据库迁移。
- 图片与缩略图文件。
- 内容哈希和重复合并。
- 过期记录及缓存清理。

### Identity Provider

首期使用本地匿名身份。未来可以加入密码、OAuth 或企业身份实现，业务层不依赖具体登录供应商。

### Sync Engine

首期只提供明确的 Local-only 实现。未来负责：

- Outbox 本地变更队列。
- 增量上传和拉取。
- 远端游标。
- 离线重试。
- 版本与冲突处理。
- 附件传输。

### Workspace Service

统一管理本机、个人和团队空间。业务查询必须显式限定 Workspace，避免不同空间之间的数据泄漏。

### Blob Storage Provider

未来负责图片或用户明确选择上传的文件附件。普通记录 JSON 与附件传输分离，并使用哈希进行校验和去重。

## 同步模型预留

未来采用增量同步：

```text
本地操作
   ↓
写入 SQLite
   ↓
追加 Outbox 操作
   ↓
后台 Push
   ↓
保存服务端版本
   ↓
按 Cursor 拉取远端变更
   ↓
合并并更新本地 Cursor
```

不会采用每次全量上传、全量下载的方式。

冲突策略初步方向：

- 删除与编辑冲突：默认删除优先。
- 收藏状态：倾向合并保留收藏。
- 置顶状态：以后更新时间较新的值为准。
- 使用次数：合并增量，不直接覆盖。
- 团队权限：始终以服务端判断为准。
- 正文冲突：保留冲突副本或采用明确版本规则。

这些规则会在真实同步服务开始实现前形成正式协议和测试。

## 团队共享预留

未来团队空间计划支持：

- 创建和加入团队。
- `owner`、`admin`、`member` 基础角色。
- 显式分享文本、图片和文件。
- 团队内容搜索和筛选。
- 分享有效期。
- 文件是否上传的明确确认。
- 服务端权限检查。
- 成员与设备撤销。
- 审计记录。

分享记录时创建团队副本：

```text
本地/个人记录
      ↓ 显式分享
团队记录副本
  source_item_id
  shared_by
  shared_at
```

本地记录的自动清理或删除不会静默删除团队副本。

## 隐私与安全

- 默认不联网、不上传。
- 可暂停监听或进入无痕状态。
- 支持排除密码管理器等指定应用。
- 日志不记录完整剪切板正文或图片内容。
- 登录令牌未来使用 Windows Credential Manager 或 DPAPI 保护。
- SQLite 和普通配置文件不保存明文令牌。
- 团队操作必须由服务端校验成员和权限。
- 文件路径同步与文件内容上传是两个独立选择。

## 本地存储建议

应用数据建议存放在用户本地应用数据目录，而不是安装目录：

```text
%LOCALAPPDATA%/ClipboardManager/
  clipboard.db
  settings.json
  logs/
  blobs/
  thumbnails/
```

最终目录名将在创建应用标识时确定。

默认策略建议：

- 普通记录最多 `1000` 条。
- 普通历史保留 `30` 天。
- 收藏记录不参与普通自动清理。
- 单张图片超过 `20 MB` 时不持久化原图。
- 图片缓存超过用户配置上限后，从最旧的非收藏内容开始清理。

## 路线图

### Phase 1：Local-first 工程骨架

- 创建解决方案和分层项目。
- 依赖注入、日志、配置和数据库迁移。
- 单实例、托盘和全局快捷键。
- 本地匿名身份、设备 ID 和 Local Workspace。
- 仓储、身份、同步、Workspace 和附件接口。

### Phase 2：文本剪切板 MVP（实施中）

- 使用 `AddClipboardFormatListener` 监听 Unicode 文本，消息线程只投递有界捕获队列。
- 剪切板占用采用有限重试，单次异常不终止监听。
- 原文保持不变；预览折叠空白；CRLF/CR 与 LF 使用一致的规范化哈希。
- 空白或超过 `2 MB` 的文本不落盘。
- 同 Workspace 相同文本事务合并，更新排序和来源并保留收藏、置顶。
- 搜索、全部/置顶/文本/收藏筛选、收藏、置顶和软删除。
- `Enter` 写回剪切板，自身写回通过一次性预期哈希标记防止重复捕获。
- 暂停监听、来源进程排除、最大条数与保留天数清理。
- SQLite 查询始终限定 Workspace 和未删除状态。

完成这一阶段后，应用应具备可日常使用的本地文本剪切板闭环。

### Phase 3：收藏库、图片与文件（实施中）

#### Phase 3A：收藏库

- 独立收藏文件夹和收藏项，不依赖历史记录生命周期。
- 唯一且不可删除的“未分类”系统文件夹。
- 新建、重命名、安全删除文件夹，非空目录默认将内容移动到“未分类”。
- 文件夹顺序和文件夹内混合内容顺序持久化。
- 文本、链接、图片和文件混排。
- 手动添加/编辑文本和链接，从历史创建收藏快照。
- 个人配置支持导出/导入独立 `.clipconfig` 迁移包；包含文件夹、文本、链接、托管图片和普通文件副本，不包含历史、团队配置、设备 ID 或本机设置，导入采用预检、合并、导入前安全备份和失败回滚。

#### Phase 3B：图片

- 图片剪切板捕获、哈希、落盘和缩略图；从文件列表复制的单张常见图片也归入“图片”筛选，但恢复时仍保持文件粘贴语义。
- 从本地选择或拖入图片并托管到应用数据目录。
- 图片收藏、预览、复制回剪切板和另存为。
- 本地路径、缩略图与未来远端 `blob_id` 分离。

#### Phase 3C：文件

- 文件列表剪切板捕获和恢复；“文件”筛选保留文档、表格、压缩包、目录及多文件列表，不混入单张 PNG/JPG 等常见图片。
- 多文件 Manifest 与路径有效性状态。
- 打开文件位置及收藏文件路径。
- 默认只保存路径引用，托管文件副本必须明确选择。

   ```powershell
   .\scripts\build-msi.ps1
   ```

## 首期验收标准

1. 文本、图片和文件列表能够稳定捕获。
2. 中文、英文、Emoji 和多行文本不乱码。
3. 连续快速复制不会造成大量重复记录或 UI 卡死。
4. 重启后历史仍然存在。
5. 搜索、收藏、置顶、软删除和清理行为正确。
6. 清理普通历史不会误删收藏。
7. 历史内容能够重新写入系统剪切板。
8. 自动粘贴失败时可以回退到手动粘贴。
9. 被排除应用的内容不写入数据库或图片目录。
10. 大图不会被长期保留在 UI 内存中。
11. 多显示器和不同 DPI 下窗口位置合理。
12. 文件不存在、图片损坏或剪切板被占用时应用不崩溃。
13. 未登录、离线时全部本地能力可用。
14. UI 不直接访问 SQLite。
15. 每条记录具有明确的 Workspace 和设备归属。
16. 本地图片路径和未来远端附件 ID 相互独立。
17. 账号、同步和团队 Provider 可以在不修改领域核心的情况下替换或新增。

## 暂不实施

以下功能不属于首期交付：

- 真实云端服务。
- 账号注册登录。
- 多设备实时同步。
- 团队成员管理。
- OCR。
- AI 摘要、改写或分类。
- 手机端。
- macOS/Linux。
- 自动上传用户复制的文件。

其中账号、同步和团队能力属于已规划路线，不是被永久排除的功能。
