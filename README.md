# 本地剪切板管理工具

一款面向 Windows 的 Local-first（本地优先）剪切板历史工具。它首先提供稳定、快速、隐私友好的本地使用体验，并从架构上为账号系统、个人多设备云同步和团队共享剪切板预留扩展能力。

> 当前状态：Phase 4 桌面体验、隐私与交付实施中。`0.4.0` 文本恢复报错 `0x800401D0` 已修复；真实系统剪切板压力探针连续 10 轮通过文本/图片/双文件列表恢复。`0.4.3` 进一步修复自动粘贴：补齐 x64 `INPUT` 原生结构、保留目标输入控件焦点，并锁定呼出前目标窗口；独立聚焦输入框端到端连续 3 轮确认文本实际填入，不再只是复制到剪切板。`0.4.4` 接入品牌 Logo：窗口图标、托盘图标、开始菜单快捷方式图标和 EXE 文件图标均已替换为自定义品牌标识。`0.4.5` 修复"双击 EXE 无任何反应"：卡住的实例不再静默吞掉启动请求，SQLite 也不再使用会互锁的共享缓存。收藏编辑/跨目录拖动、输入框快捷键和失焦隐藏仍缺 WPF 主窗口可观察实测；本机只有单显示器 96 DPI，多显示器/不同 DPI 仍未验证。详见 [`docs/acceptance/phase4-desktop-2026-09-09.md`](./docs/acceptance/phase4-desktop-2026-09-09.md)。

### 0.4.5 启动可用性修复

- 单实例唤出失败不再静默退出。若互斥体被一个不响应命名管道的进程占用，第二次启动会在重试 5 秒后弹出提示，引导用户结束残留进程，而不是让人以为"EXE 打不开"。
- SQLite 连接改用私有缓存并设置 15 秒命令超时。共享缓存会引入 busy_timeout 无法解除的进程内表级锁，读写连接可能相互死锁并把启动卡在建窗口之前。
- 接入 Serilog 文件日志，写入此前一直为空的 `%LOCALAPPDATA%\ClipboardManager\logs`。按天滚动、单文件上限 8 MB、保留 7 份。启动的每一步在执行前先记录，日志最后一行即为卡住的步骤；启动异常改为先 `LogCritical` 再弹窗，不再只存在于对话框里。此前只有 `AddConsole()`，而从资源管理器启动的 WinExe 没有控制台，所有诊断信息都被丢弃。
- 统一两条发布路径。单文件选项（`IncludeNativeLibrariesForSelfExtract`、`EnableCompressionInSingleFile`）下沉到 csproj，`build-msi.ps1` 与 `publish-single-exe.ps1` 不再各自重复。此前 MSI 脚本漏了压缩开关，产出 159 MB 的 EXE，与便携版 70 MB 并非同一份二进制。
- 已验证：占住互斥体且不开管道时弹出「无法唤出已运行的实例」；健康实例的第二次启动仍静默退出、不误报；日志文件实际生成并按序记录 6 个启动里程碑；两条发布路径产物 SHA-256 完全一致（70.53 MB）；51 项单元测试通过；重新发布的单文件 EXE 启动正常并显示主窗口。
- 未验证：原始卡死为偶发现象，本次未能复现，因此无法证明共享缓存就是其根因。该结论需等下一次卡死时用新增日志确认。

### 0.4.4 品牌 Logo 接入

- 窗口标题栏、任务栏和 Alt+Tab 切换器显示自定义品牌图标（`Assets/AppIcon.ico`）。
- 系统托盘图标替换为品牌标识，不再使用默认 `SystemIcons.Application`。
- MSI 安装包的开始菜单快捷方式和"程序和功能"列表均使用品牌图标。
- 窗口标题栏左侧显示品牌 Logo 图片（`Assets/AppIcon.png`），与文字标题并排。
- Logo 资产由 `scripts/build-logo-assets.py` 从源图生成：裁剪符号区域、白底转透明、多尺寸 ICO。

### 0.4.3 已固化桌面基线

- 文本写回采用有效窗口 owner 的 Win32 路径优先，避免 `OpenClipboard(IntPtr.Zero)` 与 OLE 失败后的占用竞态再次引发 `0x800401D0`。
- 自动粘贴锁定 `Alt+V` 呼出前的目标窗口，不允许后续前台事件替换；恢复顶层窗口时保留原输入控件焦点。
- Windows x64 `INPUT` 原生结构尺寸为 40 字节；只有 `SendInput` 完整发送 4/4 个 Ctrl+V 事件且目标输入框正文实际变化，才视为自动粘贴通过。
- 当前 MSI 已安装为 `0.4.3-phase4`。高权限目标或主动阻止模拟输入的应用受 Windows UIPI/应用安全策略限制，此时仍只保证剪切板内容可手动粘贴。
- 回归时运行 `tools/ClipboardManager.DesktopProbe`；探针覆盖文本、PNG、双文件列表、Win32 owner 写入与聚焦输入框自动粘贴，并在结束时恢复原剪切板。

## 产品目标

工具需要解决以下核心问题：

- 自动保存复制过的文本、图片和文件列表。
- 使用全局快捷键快速呼出历史面板。
- 搜索、筛选、收藏、置顶和删除历史记录。
- 将历史内容重新写回系统剪切板，并可选自动粘贴。
- 数据默认只保存在本机，离线和未登录时完整可用。
- 后续可平滑接入账号、多设备同步和团队显式分享，而不重构本地捕获主链路。

## 产品原则

### 本地优先

- 本地剪切板功能不依赖账号、网络或云端服务。
- SQLite 是当前设备上的即时数据源。
- 网络故障不得阻塞剪切板捕获、搜索和重新使用。
- 云端能力是增量扩展，而不是本地功能的前置条件。

### 隐私默认

- 新捕获内容默认进入本机空间。
- 不自动上传剪切板历史。
- 不自动把个人内容发布到团队。
- 提供暂停监听、应用排除、自动清理和彻底清除本地数据能力。

### 显式团队分享

未来的团队共享不是“把整个个人剪切板同步给团队”。用户需要显式选择记录并分享到指定团队空间。分享会创建独立团队副本，本地原记录仍保持原有归属。

## 首期范围

首期面向 Windows，计划实现：

- 文本、图片和文件列表捕获。
- 剪切板历史持久化。
- 全局快捷键显示/隐藏面板。
- 搜索和类型筛选。
- 收藏、置顶、删除和清空。
- 历史内容重新写回剪切板。
- 可选自动粘贴。
- 系统托盘、单实例和开机启动。
- 来源应用记录和应用排除。
- 图片缩略图、缓存上限和过期清理。
- 多显示器和 DPI 适配。

首期不会实现真实的账号服务、云端 API、跨设备同步或团队管理，但会建立必要的领域模型和抽象接口。

主窗口采用紧凑的浮动面板结构：

```text

│ 标题 / 置顶 / 窗口操作      │
├─────────────────────────────┤
│ 搜索剪切板历史               │
├─────────────────────────────┤
│ 全部 置顶 文本 图片 文件 收藏│
├─────────────────────────────┤
│                             │

│                             │
├─────────────────────────────┤
```

不同内容类型使用不同的记录预览：

- 文本：正文摘要、来源应用和时间。
- 图片：缩略图、尺寸、大小和来源。
- 文件：文件名、父目录、数量和有效状态。

|---|---|
| `Alt+V` | 显示或隐藏面板 |

## 技术方案

默认技术基线：

- [.NET 8](https://dotnet.microsoft.com/)
- WPF
- Windows Clipboard/Win32 API
- SQLite
- Microsoft.Extensions.DependencyInjection
- Microsoft.Extensions.Logging

选择 WPF 的主要原因是项目首期专注 Windows，需要稳定处理原生剪切板消息、全局快捷键、托盘、窗口焦点、自动粘贴和多显示器行为。

## 架构

计划采用分层结构：

```text
src/
  ClipboardManager.Domain/
  ClipboardManager.Application/
  ClipboardManager.Infrastructure/
  ClipboardManager.Windows/
tests/
  ClipboardManager.Domain.Tests/
  ClipboardManager.Application.Tests/
  ClipboardManager.Infrastructure.Tests/
```

```text
Windows UI / Win32
        ↓
Application Use Cases
        ↓
Domain Model & Contracts
        ↑
Infrastructure: SQLite / Files / Future Remote Providers
```

核心约束：

- UI 不直接访问 SQLite。
- 领域层不依赖 WPF、数据库或远端 SDK。
- 剪切板监听器不直接执行网络同步。
- 本地写入先完成，同步通过独立引擎异步处理。
- 云端失败不影响本地使用。

完整的工程约束见 [`AGENTS.md`](./AGENTS.md)。

## Local-first 数据归属

所有剪切板记录都属于一个 Workspace：

| Workspace 类型 | 用途 | 首期状态 |
|---|---|---|
| `Local` | 本机剪切板历史 | 实现 |
| `Personal` | 个人云端、多设备同步 | 预留 |
| `Team` | 团队共享剪切板 | 预留 |

每条记录从一开始就具有：

- 跨设备唯一的 UUID。
- `workspace_id`。
- `device_id`。
- 创建、更新和软删除时间。
- 本地与远端版本字段。
- 同步状态。

这样后续启用多设备同步时，不需要重做主键、数据归属和删除模型。

## 核心模块

### Clipboard Capture

负责：

- 注册 Windows 剪切板更新监听。
- 读取文本、图片和文件格式。
- 有限重试被占用的剪切板。
- 获取来源进程。
- 避免工具自身写回产生捕获循环。
- 将系统格式转换为领域模型。

### Application

负责：

- 捕获记录入库。
- 搜索和筛选。
- 收藏、置顶和删除。
- 重新使用历史内容。
- Workspace 上下文。
- 清理策略。
- 未来同步编排。

### Local Storage

负责：

- SQLite 仓储。
- 数据库迁移。
- 图片与缩略图文件。
- 内容哈希和重复合并。
- 过期记录及缓存清理。

### Identity Provider

首期使用本地匿名身份。未来可以加入密码、OAuth 或企业身份实现，业务层不依赖具体登录供应商。

### Sync Engine

首期只提供明确的 Local-only 实现。未来负责：

- Outbox 本地变更队列。
- 增量上传和拉取。
- 远端游标。
- 离线重试。
- 版本与冲突处理。
- 附件传输。

### Workspace Service

统一管理本机、个人和团队空间。业务查询必须显式限定 Workspace，避免不同空间之间的数据泄漏。

### Blob Storage Provider

未来负责图片或用户明确选择上传的文件附件。普通记录 JSON 与附件传输分离，并使用哈希进行校验和去重。

## 同步模型预留

未来采用增量同步：

```text
本地操作
   ↓
写入 SQLite
   ↓
追加 Outbox 操作
   ↓
后台 Push
   ↓
保存服务端版本
   ↓
按 Cursor 拉取远端变更
   ↓
合并并更新本地 Cursor
```

不会采用每次全量上传、全量下载的方式。

冲突策略初步方向：

- 删除与编辑冲突：默认删除优先。
- 收藏状态：倾向合并保留收藏。
- 置顶状态：以后更新时间较新的值为准。
- 使用次数：合并增量，不直接覆盖。
- 团队权限：始终以服务端判断为准。
- 正文冲突：保留冲突副本或采用明确版本规则。

这些规则会在真实同步服务开始实现前形成正式协议和测试。

## 团队共享预留

未来团队空间计划支持：

- 创建和加入团队。
- `owner`、`admin`、`member` 基础角色。
- 显式分享文本、图片和文件。
- 团队内容搜索和筛选。
- 分享有效期。
- 文件是否上传的明确确认。
- 服务端权限检查。
- 成员与设备撤销。
- 审计记录。

分享记录时创建团队副本：

```text
本地/个人记录
      ↓ 显式分享
团队记录副本
  source_item_id
  shared_by
  shared_at
```

本地记录的自动清理或删除不会静默删除团队副本。

## 隐私与安全

- 默认不联网、不上传。
- 可暂停监听或进入无痕状态。
- 支持排除密码管理器等指定应用。
- 日志不记录完整剪切板正文或图片内容。
- 登录令牌未来使用 Windows Credential Manager 或 DPAPI 保护。
- SQLite 和普通配置文件不保存明文令牌。
- 团队操作必须由服务端校验成员和权限。
- 文件路径同步与文件内容上传是两个独立选择。

## 本地存储建议

应用数据建议存放在用户本地应用数据目录，而不是安装目录：

```text
%LOCALAPPDATA%/ClipboardManager/
  clipboard.db
  settings.json
  logs/
  blobs/
  thumbnails/
```

最终目录名将在创建应用标识时确定。

默认策略建议：

- 普通记录最多 `1000` 条。
- 普通历史保留 `30` 天。
- 收藏记录不参与普通自动清理。
- 单张图片超过 `20 MB` 时不持久化原图。
- 图片缓存超过用户配置上限后，从最旧的非收藏内容开始清理。

## 路线图

### Phase 1：Local-first 工程骨架

- 创建解决方案和分层项目。
- 依赖注入、日志、配置和数据库迁移。
- 单实例、托盘和全局快捷键。
- 本地匿名身份、设备 ID 和 Local Workspace。
- 仓储、身份、同步、Workspace 和附件接口。

### Phase 2：文本剪切板 MVP（实施中）

- 使用 `AddClipboardFormatListener` 监听 Unicode 文本，消息线程只投递有界捕获队列。
- 剪切板占用采用有限重试，单次异常不终止监听。
- 原文保持不变；预览折叠空白；CRLF/CR 与 LF 使用一致的规范化哈希。
- 空白或超过 `2 MB` 的文本不落盘。
- 同 Workspace 相同文本事务合并，更新排序和来源并保留收藏、置顶。
- 搜索、全部/置顶/文本/收藏筛选、收藏、置顶和软删除。
- `Enter` 写回剪切板，自身写回通过一次性预期哈希标记防止重复捕获。
- 暂停监听、来源进程排除、最大条数与保留天数清理。
- SQLite 查询始终限定 Workspace 和未删除状态。

完成这一阶段后，应用应具备可日常使用的本地文本剪切板闭环。

### Phase 3：收藏库、图片与文件（实施中）

#### Phase 3A：收藏库

- 独立收藏文件夹和收藏项，不依赖历史记录生命周期。
- 唯一且不可删除的“未分类”系统文件夹。
- 新建、重命名、安全删除文件夹，非空目录默认将内容移动到“未分类”。
- 文件夹顺序和文件夹内混合内容顺序持久化。
- 文本、链接、图片和文件混排。
- 手动添加/编辑文本和链接，从历史创建收藏快照。

#### Phase 3B：图片

- 图片剪切板捕获、哈希、落盘和缩略图。
- 从本地选择或拖入图片并托管到应用数据目录。
- 图片收藏、预览、复制回剪切板和另存为。
- 本地路径、缩略图与未来远端 `blob_id` 分离。

#### Phase 3C：文件

- 文件列表剪切板捕获和恢复。
- 多文件 Manifest 与路径有效性状态。
- 打开文件位置及收藏文件路径。
- 默认只保存路径引用，托管文件副本必须明确选择。

### Phase 4：桌面体验、隐私与交付（实施中）

按以下顺序实施，完成代码不等于完成桌面验收：

## 首期验收标准

1. 文本、图片和文件列表能够稳定捕获。
2. 中文、英文、Emoji 和多行文本不乱码。
3. 连续快速复制不会造成大量重复记录或 UI 卡死。
4. 重启后历史仍然存在。
5. 搜索、收藏、置顶、软删除和清理行为正确。
6. 清理普通历史不会误删收藏。
7. 历史内容能够重新写入系统剪切板。
8. 自动粘贴失败时可以回退到手动粘贴。
9. 被排除应用的内容不写入数据库或图片目录。
10. 大图不会被长期保留在 UI 内存中。
11. 多显示器和不同 DPI 下窗口位置合理。
12. 文件不存在、图片损坏或剪切板被占用时应用不崩溃。
13. 未登录、离线时全部本地能力可用。
14. UI 不直接访问 SQLite。
15. 每条记录具有明确的 Workspace 和设备归属。
16. 本地图片路径和未来远端附件 ID 相互独立。
17. 账号、同步和团队 Provider 可以在不修改领域核心的情况下替换或新增。

## 暂不实施

- 真实云端服务。
- 账号注册登录。
- 多设备实时同步。
- 团队成员管理。
- OCR。
- AI 摘要、改写或分类。
- 手机端。
- macOS/Linux。
- 自动上传用户复制的文件。

其中账号、同步和团队能力属于已规划路线，不是被永久排除的功能。
