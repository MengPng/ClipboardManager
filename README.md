# 本地剪切板管理工具

一款面向 Windows 的 Local-first（本地优先）剪切板历史工具。它首先提供稳定、快速、隐私友好的本地使用体验，并从架构上为账号系统、个人多设备云同步和团队共享剪切板预留扩展能力。

## 下载与安装

正式版本通过 GitHub Releases 分发：

- `ClipboardManager-<version>-win-x64.exe`：推荐下载。单个文件即可运行，已内置备份恢复组件，无需安装 .NET 或下载其他文件。
- `ClipboardManager-<version>-win-x64-portable.zip`：免安装便携包，解压后运行 `ClipboardManager.exe`。
- `SHA256SUMS.txt`：发布文件完整性校验。

两个版本均为 Windows x64 自包含发布，目标电脑无需预装 .NET 运行环境。MSI 暂不进入正式 Release，待安装兼容性验收完成后再恢复分发。当前产物尚未进行商业代码签名，Windows 可能显示“未知发布者”。

> 当前状态：Phase 4 桌面体验、隐私与交付实施中。`0.6.2` 将主面板默认尺寸收紧为 420 × 540，并允许缩小至 400 × 450；`0.6.1` 修复发布版数据库 schema 落后问题，并加入最终 EXE/MSI 版本与 schema 硬性校验；schema 4 真实用户数据库已安全备份并升级到 schema 5，MSI 安装及启动通过。`0.4.0` 文本恢复报错 `0x800401D0` 已修复；真实系统剪切板压力探针连续 10 轮通过文本/图片/双文件列表恢复。`0.4.3` 进一步修复自动粘贴：补齐 x64 `INPUT` 原生结构、保留目标输入控件焦点，并锁定呼出前目标窗口；独立聚焦输入框端到端连续 3 轮确认文本实际填入，不再只是复制到剪切板。`0.4.4` 接入品牌 Logo：窗口图标、托盘图标、开始菜单快捷方式图标和 EXE 文件图标均已替换为自定义品牌标识。`0.4.5` 修复"双击 EXE 无任何反应"：卡住的实例不再静默吞掉启动请求，SQLite 也不再使用会互锁的共享缓存。2026-09-09 完成桌面界面重构：主题资源集中化、Windows 11 亚克力材质、左侧导航与列表密度选项。随后导航移到顶部胶囊分段控件，并拆分为「历史 / 个人配置 / 团队配置」：团队配置是**仅本机**的第二个 Workspace，没有账号、服务端和同步，剪切板捕获仍永久落在本机空间；两个配置空间共用同一套界面控件，并新增 `Alt+↑/↓` 手动排序。已实测三个空间的渲染、跨空间隔离、排序持久化（跨进程重启）；收藏编辑/跨目录拖动、输入框快捷键和失焦隐藏仍缺 WPF 主窗口可观察实测；本机只有单显示器 96 DPI，多显示器/不同 DPI 仍未验证。详见 [`docs/acceptance/phase4-desktop-2026-09-09.md`](./docs/acceptance/phase4-desktop-2026-09-09.md)。

### 桌面界面重构（2026-09-09）

- `0.6.5`：移除“逐条发送”；个人配置支持添加本地文件夹映射、修改简称，并通过双击或右键打开对应目录。
- `0.6.3`：配置项名称可用于文本、链接、图片和文件；图片与文件列表隐藏本地路径，文本及链接正文仅显示一行预览，图片可从右键菜单打开所在位置。

- 颜色、字体、圆角与间距从散落的内联值集中到 `Themes/Palette.xaml`；`Themes/Controls.xaml` 重写了按钮、输入框、复选框、列表、滚动条、页签、右键菜单和工具提示模板。此前主窗口只定义了 3 个画刷，其余控件沿用 WPF 默认外观，且十余处颜色直接写在 `TextBlock` 与 `Border` 上，无法整体换肤。
- 主窗口改为无系统标题栏 + `WindowChrome`，通过 `DwmSetWindowAttribute` 申请亚克力背景与圆角。刻意不使用 `AllowsTransparency`：分层窗口会让 DWM 背景失效。背景不可用时回落到不透明填充，因为透明合成目标在没有背景时会渲染成黑色。
- 视图切换保留 `TabControl`（仅重写模板为左侧导航），窗口的键盘、拖放和刷新逻辑都基于 `MainTabs.SelectedIndex`，换控件类型只会带来无谓的改写风险。
- 修复列表计数不更新：首次刷新发生在窗口显示之前，此时页签模板尚未应用、`SelectedIndex` 仍为 `-1`，原先的 `== 0` 判断会让历史计数静默丢弃，底栏一直显示「0 条记录」。判断改为以「是否收藏页」为准。
- 暂停按钮改为切换控件后，若 `SetPausedAsync` 失败会在 `finally` 中以监听器真实状态回正图标，不再停留在未发生的暂停态。

### 0.4.5 启动可用性修复

- 单实例唤出失败不再静默退出。若互斥体被一个不响应命名管道的进程占用，第二次启动会在重试 5 秒后弹出提示，引导用户结束残留进程，而不是让人以为"EXE 打不开"。
- SQLite 连接改用私有缓存并设置 15 秒命令超时。共享缓存会引入 busy_timeout 无法解除的进程内表级锁，读写连接可能相互死锁并把启动卡在建窗口之前。
- 接入 Serilog 文件日志，写入此前一直为空的 `%LOCALAPPDATA%\ClipboardManager\logs`。按天滚动、单文件上限 8 MB、保留 7 份。启动的每一步在执行前先记录，日志最后一行即为卡住的步骤；启动异常改为先 `LogCritical` 再弹窗，不再只存在于对话框里。此前只有 `AddConsole()`，而从资源管理器启动的 WinExe 没有控制台，所有诊断信息都被丢弃。
- 统一两条发布路径。单文件选项（`IncludeNativeLibrariesForSelfExtract`、`EnableCompressionInSingleFile`）下沉到 csproj，`build-msi.ps1` 与 `publish-single-exe.ps1` 不再各自重复。此前 MSI 脚本漏了压缩开关，产出 159 MB 的 EXE，与便携版 70 MB 并非同一份二进制。
- 已验证：占住互斥体且不开管道时弹出「无法唤出已运行的实例」；健康实例的第二次启动仍静默退出、不误报；日志文件实际生成并按序记录 6 个启动里程碑；两条发布路径产物 SHA-256 完全一致（70.53 MB）；51 项单元测试通过；重新发布的单文件 EXE 启动正常并显示主窗口。
- 未验证：原始卡死为偶发现象，本次未能复现，因此无法证明共享缓存就是其根因。该结论需等下一次卡死时用新增日志确认。

- 窗口标题栏、任务栏和 Alt+Tab 切换器显示自定义品牌图标（`Assets/AppIcon.ico`）。
- 系统托盘图标替换为品牌标识，不再使用默认 `SystemIcons.Application`。

### 0.4.3 已固化桌面基线

- 文本写回采用有效窗口 owner 的 Win32 路径优先，避免 `OpenClipboard(IntPtr.Zero)` 与 OLE 失败后的占用竞态再次引发 `0x800401D0`。
- 自动粘贴锁定 `Alt+V` 呼出前的目标窗口，不允许后续前台事件替换；恢复顶层窗口时保留原输入控件焦点。

- 回归时运行 `tools/ClipboardManager.DesktopProbe`；探针覆盖文本、PNG、双文件列表、Win32 owner 写入与聚焦输入框自动粘贴，并在结束时恢复原剪切板。

## 产品目标

工具需要解决以下核心问题：

- 自动保存复制过的文本、图片和文件列表。
- 使用全局快捷键快速呼出历史面板。
- 搜索、筛选、收藏、置顶和删除历史记录。
- 将历史内容重新写回系统剪切板，并可选自动粘贴。
- 数据默认只保存在本机，离线和未登录时完整可用。
- 后续可平滑接入账号、多设备同步和团队显式分享，而不重构本地捕获主链路。

## 产品原则

### 本地优先

- 本地剪切板功能不依赖账号、网络或云端服务。
- SQLite 是当前设备上的即时数据源。
- 网络故障不得阻塞剪切板捕获、搜索和重新使用。
- 云端能力是增量扩展，而不是本地功能的前置条件。

### 隐私默认

- 新捕获内容默认进入本机空间。
- 不自动上传剪切板历史。
- 不自动把个人内容发布到团队。
- 提供暂停监听、应用排除、自动清理和彻底清除本地数据能力。

### 显式团队分享

未来的团队共享不是“把整个个人剪切板同步给团队”。用户需要显式选择记录并分享到指定团队空间。分享会创建独立团队副本，本地原记录仍保持原有归属。

## 首期范围

首期面向 Windows，计划实现：

- 文本、图片和文件列表捕获。
- 剪切板历史持久化。
- 全局快捷键显示/隐藏面板。
- 搜索和类型筛选。
- 收藏、置顶、删除和清空。
- 历史内容重新写回剪切板。
- 可选自动粘贴。
- 系统托盘、单实例、托盘一键重启和开机启动。
- 首次启动询问是否启用 24/48/72 小时自动完整备份；备份按“本机名-日期时间-剪切板备份”命名，同一自然日的新自动备份替换当天旧文件，设置页仍支持手动导出。
- 来源应用记录和应用排除。
- 图片缩略图、缓存上限和过期清理。
- 多显示器和 DPI 适配。

首期不会实现真实的账号服务、云端 API、跨设备同步或团队管理，但会建立必要的领域模型和抽象接口。

## 界面方向

主窗口是一块半透明的浮动面板：无系统标题栏，圆角，背景由 Windows 11 DWM 亚克力材质透出，视觉层次参考 macOS 的 vibrancy——导航与文件夹栏保持通透，列表表面接近不透明以保证正文对比度。

```text
┌──────────────────────────────────────────────┐
│ 剪切板 · 本机        ● 监听  钉住 暂停 设置 ✕ │
├──────────┬───────────────────────────────────┤
│      历史 │ 个人配置 │ 团队配置                │
├──────────────────────────────────────────────┤
│ 搜索历史                          存入配置    │
│ 全部 置顶 文本 图片 文件 快速收藏             │
├──────────────────────────────────────────────┤
│ 历史记录虚拟化列表                            │
│                                              │
├──────────────────────────────────────────────┤
│ 记录数量 / Workspace          快捷键提示      │
└──────────────────────────────────────────────┘
```

- 三个视图入口是顶部居中的胶囊分段控件，与筛选胶囊同一套视觉语言。
- 「个人配置」与「团队配置」共用同一套文件夹栏与内容栏控件，切换只改变目标 Workspace，不重建界面。「团队配置」顶部常驻提示说明它目前只保存在本机。
- 筛选项是可换行的胶囊按钮（`RadioButton` 分组），当前筛选是真实控件状态而非由代码设置字重。
- 钉住、暂停、设置和隐藏为图标按钮，各自带 `AutomationProperties.Name`，因为图标本身是私有区码位。
- 列表行高提供宽松与紧凑两档，由设置项 `CompactList` 持久化，切换后立即生效且不重建缩略图。

主题实现约定：

- 所有颜色、字体、圆角与行距集中在 [`Themes/Palette.xaml`](./src/ClipboardManager.Windows/Themes/Palette.xaml)，控件模板集中在 [`Themes/Controls.xaml`](./src/ClipboardManager.Windows/Themes/Controls.xaml)。两者按顺序合并进 `App.xaml`。
- 界面代码不得内联画刷。需要换主题或做暗色时只应改调色板，不应逐个控件修改。
- 亚克力只使用有文档的 `DwmSetWindowAttribute`；不支持时（Windows 10 或调用被拒）降级为不透明背景，不调用未公开的 `SetWindowCompositionAttribute`。

不同内容类型使用不同的记录预览：

- 文本：正文摘要、来源应用和时间。
- 图片：缩略图、尺寸、大小和来源。
- 文件：文件名、父目录、数量和有效状态。

计划的默认键盘操作：

| 快捷键 | 行为 |
|---|---|
| `Alt+V` | 显示或隐藏面板 |
| `Up` / `Down` | 切换记录 |
| `Enter` | 将选中内容写回剪切板 |
| `Ctrl+Enter` | 写回并尝试自动粘贴 |
| `Ctrl+F` | 聚焦搜索框 |
| `Delete` | 删除选中记录 |
| `Ctrl+D` | 历史视图：把选中记录快速存入「个人配置」的未分类 |
| `Ctrl+P` | 置顶或取消置顶 |
| `Alt+Up` / `Alt+Down` | 配置视图：把选中项上移 / 下移一位 |
| `Esc` | 清空搜索或关闭面板 |

`Ctrl+D` 永远写入「个人配置」，不会因为当前停在「团队配置」而改变目标；放入团队配置只能通过「存入配置」目录选择器显式完成。历史筛选里的「快速收藏」是记录自身的 `is_favorite` 标记，与配置库是两回事。

快捷键最终将允许配置。

## Local-first 数据归属

所有剪切板记录都属于一个 Workspace：

| Workspace 类型 | 用途 | 首期状态 |
|---|---|---|
| `Local` | 本机剪切板历史，以及「个人配置」库 | 实现 |
| `Personal` | 个人云端、多设备同步 | 预留 |
| `Team` | 「团队配置」库，**目前仅本机**，无账号、无服务端、无同步；真正的团队共享仍是预留 | 部分实现 |

剪切板捕获永久锚定在 `Local`。界面切换到「团队配置」只改变配置库的查询目标，不会改变新复制内容的归属。详见 [`docs/adr/0002-team-config-local-only-workspace.md`](./docs/adr/0002-team-config-local-only-workspace.md)。

每条记录从一开始就具有：

- 跨设备唯一的 UUID。
- `workspace_id`。
- `device_id`。
- 创建、更新和软删除时间。
- 本地与远端版本字段。
- 同步状态。

这样后续启用多设备同步时，不需要重做主键、数据归属和删除模型。

## 核心模块

### Clipboard Capture

负责：

- 注册 Windows 剪切板更新监听。
- 读取文本、图片和文件格式。
- 有限重试被占用的剪切板。
- 获取来源进程。
- 避免工具自身写回产生捕获循环。
- 将系统格式转换为领域模型。

### Application

负责：

- 捕获记录入库。
- 搜索和筛选。
- 收藏、置顶和删除。
- 重新使用历史内容。
- Workspace 上下文。
- 清理策略。
- 未来同步编排。

### Local Storage

负责：

- SQLite 仓储。
- 数据库迁移。
- 图片与缩略图文件。
- 内容哈希和重复合并。
- 过期记录及缓存清理。

### Identity Provider

首期使用本地匿名身份。未来可以加入密码、OAuth 或企业身份实现，业务层不依赖具体登录供应商。

### Sync Engine

首期只提供明确的 Local-only 实现。未来负责：

- Outbox 本地变更队列。
- 增量上传和拉取。
- 远端游标。
- 离线重试。
- 版本与冲突处理。
- 附件传输。

### Workspace Service

统一管理本机、个人和团队空间。业务查询必须显式限定 Workspace，避免不同空间之间的数据泄漏。

### Blob Storage Provider

未来负责图片或用户明确选择上传的文件附件。普通记录 JSON 与附件传输分离，并使用哈希进行校验和去重。

删除采用软删除。这样未来某台离线设备删除记录后，其他设备能够通过墓碑变更得知删除结果。

## 同步模型预留

未来采用增量同步：

```text
本地操作
   ↓
写入 SQLite
   ↓
追加 Outbox 操作
   ↓
后台 Push
   ↓
保存服务端版本
   ↓
按 Cursor 拉取远端变更
   ↓
合并并更新本地 Cursor
```

不会采用每次全量上传、全量下载的方式。

冲突策略初步方向：

- 删除与编辑冲突：默认删除优先。
- 收藏状态：倾向合并保留收藏。
- 置顶状态：以后更新时间较新的值为准。
- 使用次数：合并增量，不直接覆盖。
- 团队权限：始终以服务端判断为准。
- 正文冲突：保留冲突副本或采用明确版本规则。

这些规则会在真实同步服务开始实现前形成正式协议和测试。

## 团队共享预留

未来团队空间计划支持：

- 创建和加入团队。
- `owner`、`admin`、`member` 基础角色。
- 显式分享文本、图片和文件。
- 团队内容搜索和筛选。
- 分享有效期。
- 文件是否上传的明确确认。
- 服务端权限检查。
- 成员与设备撤销。
- 审计记录。

分享记录时创建团队副本：

```text
本地/个人记录
      ↓ 显式分享
团队记录副本
  source_item_id
  shared_by
  shared_at
```

本地记录的自动清理或删除不会静默删除团队副本。

## 隐私与安全

- 默认不联网、不上传。
- 可暂停监听或进入无痕状态。
- 支持排除密码管理器等指定应用。
- 日志不记录完整剪切板正文或图片内容。
- 登录令牌未来使用 Windows Credential Manager 或 DPAPI 保护。
- SQLite 和普通配置文件不保存明文令牌。
- 团队操作必须由服务端校验成员和权限。
- 文件路径同步与文件内容上传是两个独立选择。

## 本地存储建议

应用数据建议存放在用户本地应用数据目录，而不是安装目录：

```text
%LOCALAPPDATA%/ClipboardManager/
  clipboard.db
  settings.json
  logs/
  blobs/
  thumbnails/
```

最终目录名将在创建应用标识时确定。

默认策略建议：

- 普通记录最多 `1000` 条。
- 普通历史保留 `30` 天。
- 收藏记录不参与普通自动清理。
- 单张图片超过 `20 MB` 时不持久化原图。
- 图片缓存超过用户配置上限后，从最旧的非收藏内容开始清理。

## 路线图

### Phase 1：Local-first 工程骨架

- 创建解决方案和分层项目。
- 依赖注入、日志、配置和数据库迁移。
- 单实例、托盘和全局快捷键。
- 本地匿名身份、设备 ID 和 Local Workspace。
- 仓储、身份、同步、Workspace 和附件接口。

### Phase 2：文本剪切板 MVP（实施中）

- 使用 `AddClipboardFormatListener` 监听 Unicode 文本，消息线程只投递有界捕获队列。
- 剪切板占用采用有限重试，单次异常不终止监听。
- 原文保持不变；预览折叠空白；CRLF/CR 与 LF 使用一致的规范化哈希。
- 空白或超过 `2 MB` 的文本不落盘。
- 同 Workspace 相同文本事务合并，更新排序和来源并保留收藏、置顶。
- 搜索、全部/置顶/文本/收藏筛选、收藏、置顶和软删除。
- `Enter` 写回剪切板，自身写回通过一次性预期哈希标记防止重复捕获。
- 暂停监听、来源进程排除、最大条数与保留天数清理。
- SQLite 查询始终限定 Workspace 和未删除状态。

完成这一阶段后，应用应具备可日常使用的本地文本剪切板闭环。

### Phase 3：收藏库、图片与文件（实施中）

#### Phase 3A：收藏库

- 独立收藏文件夹和收藏项，不依赖历史记录生命周期。
- 唯一且不可删除的“未分类”系统文件夹。
- 新建、重命名、安全删除文件夹，非空目录默认将内容移动到“未分类”。
- 文件夹顺序和文件夹内混合内容顺序持久化。
- 文本、链接、图片和文件混排。
- 手动添加/编辑文本和链接，从历史创建收藏快照。
- 个人配置支持导出/导入独立 `.clipconfig` 迁移包；包含文件夹、文本、链接、托管图片和普通文件副本，不包含历史、团队配置、设备 ID 或本机设置，导入采用预检、合并、导入前安全备份和失败回滚。

#### Phase 3B：图片

- 图片剪切板捕获、哈希、落盘和缩略图；从文件列表复制的单张常见图片也归入“图片”筛选，但恢复时仍保持文件粘贴语义。
- 从本地选择或拖入图片并托管到应用数据目录。
- 图片收藏、预览、复制回剪切板和另存为。
- 本地路径、缩略图与未来远端 `blob_id` 分离。

#### Phase 3C：文件

- 文件列表剪切板捕获和恢复；“文件”筛选保留文档、表格、压缩包、目录及多文件列表，不混入单张 PNG/JPG 等常见图片。
- 多文件 Manifest 与路径有效性状态。
- 打开文件位置及收藏文件路径。
- 默认只保存路径引用，托管文件副本必须明确选择。

## 首期验收标准

1. 文本、图片和文件列表能够稳定捕获。
2. 中文、英文、Emoji 和多行文本不乱码。
3. 连续快速复制不会造成大量重复记录或 UI 卡死。
4. 重启后历史仍然存在。
5. 搜索、收藏、置顶、软删除和清理行为正确。
6. 清理普通历史不会误删收藏。
7. 历史内容能够重新写入系统剪切板。
8. 自动粘贴失败时可以回退到手动粘贴。
9. 被排除应用的内容不写入数据库或图片目录。
10. 大图不会被长期保留在 UI 内存中。
11. 多显示器和不同 DPI 下窗口位置合理。
12. 文件不存在、图片损坏或剪切板被占用时应用不崩溃。
13. 未登录、离线时全部本地能力可用。
14. UI 不直接访问 SQLite。
15. 每条记录具有明确的 Workspace 和设备归属。
16. 本地图片路径和未来远端附件 ID 相互独立。
17. 账号、同步和团队 Provider 可以在不修改领域核心的情况下替换或新增。
