# 配置订阅同步（0.9.0 第一期）

## 决定（已确认）
1. 发布者手动发布新版本；"自动发布"作为可选开关（改动后 60 秒无新改动才发布）。
2. 订阅者默认"提示后更新"，可选自动更新、跳过此版本、停留当前版本。
3. 配对使用 6 位配对码。
4. 第一期内容：文本、图片、文件、链接（历史里的"链接"类型，即文本中可识别的 URL）。

## 范围
- 只同步"个人配置"（文件夹、条目、待办之外的配置内容）。**剪切板历史不参与同步**。
- 同步是单向的：发布者 → 订阅者。订阅者的受管文件夹只读；想修改就"复制到我的配置"。
- 一台电脑可同时发布多套配置、订阅多个发布者。

## 模型
- **发布**：选择一个个人配置文件夹 → 设为"已发布"，生成 `publishedId`（UUID）与名称。每次"发布新版本"版本号 +1（v1、v2…），生成内容快照与哈希。
- **订阅**：在"共享"页选择已配对的发布者与配置，订阅后本机生成"受管文件夹"（标注"来自 <发布者> · v<n>"），内容只读。
- 版本单调递增：订阅者拒绝降级（版本 ≤ 当前版本的包直接拒收）。
- 每个订阅最多保留最近 3 个本地版本快照，用于回退。

## 发现与配对
- 发现：UDP 组播，使用独立端口（默认 TCP/UDP 53318，避免与 LocalSend 的 53317 冲突）。广播内容只含：协议版本、设备名、发布的配置名称与版本号、证书指纹前缀。**不含内容**。
- 配对：发布者点"生成配对码"，显示 6 位数字，5 分钟有效。订阅者输入后，双方用 HMAC-SHA256(配对码, 双方证书指纹 ‖ 双方 nonce) 互相验证，不在网络上明文传输配对码。
- 失败 5 次后配对码作废，需重新生成。
- 配对成功后保存对方证书指纹（pin），之后只接受该指纹的连接。
- 取消配对：发布者可移除订阅者；订阅者可取消订阅（会询问是否删除受管文件夹）。

## 传输
- 发布者启动本机 HTTPS 监听（自签证书，首次运行生成，指纹持久化）。仅对已配对指纹开放配置接口；未配对的请求只能访问配对端点。
- 接口：`GET /v1/manifest`（版本、哈希、条目清单，≤ 4 MB）、`GET /v1/package?version=n`（迁移包，≤ 200 MB）。
- 包内每个资源有 SHA-256，导入前逐个校验；清单 `IncludedBytes` 与实际总和必须一致。
- 大小上限：单文件 ≤ 50 MB，单包 ≤ 200 MB（替换现有迁移包的 20 GB 上限，**仅针对网络接收路径**，本地导入保持原限制）。
- 超时与断点：单次请求 60 秒超时；下载失败保留临时文件，重试时从头开始（第一期不做分块续传）。

## 内容类型
| 类型 | 处理 |
|---|---|
| 文本 | 原样保存；长度沿用现有上限 |
| 图片 | PNG/JPEG，沿用现有图片校验 |
| 链接 | 保存为文本记录，并在 UI 中标注"链接"；只接受 http/https，显示域名，打开前经系统浏览器（与现有行为一致） |
| 文件 | 体积上限 50 MB；文件名做规范化（去掉路径分隔符、保留扩展名）；**可执行类扩展名（.exe .bat .cmd .ps1 .vbs .js .lnk .msi .scr .com .jar 等）默认标记为"高风险"，导入时需要单独确认，且不自动打开** |

## 订阅者的安全要求
- 首次订阅或版本含高风险文件时，显示预览：条目数、类型分布、高风险文件列表、发布者名称与指纹前缀。
- 受管文件夹与用户自己的配置**物理隔离**（单独的文件夹与独立的 folder 标记），用户自己的配置不被自动改写。
- 同步内容不会自动粘贴或自动执行。
- 对方发来的文本可能含误导性内容，UI 上在受管条目旁显示来源标记。

## 更新流程（默认"提示后更新"）
1. 订阅者定期（默认 30 分钟）或手动检查 `GET /v1/manifest`。
2. 发现新版本 → 托盘/页面提示"<发布者> 发布了 v<n>"。
3. 点开显示变化摘要：新增 N、修改 N、删除 N（按条目 ID 比较）。
4. 确认后：先备份当前受管内容（快照），再下载、校验哈希、原子替换。任何一步失败都保留原版本。
5. 可选：自动更新（该订阅单独设置）；跳过此版本（记录版本号，不再提示该版本）；停留当前版本。

## 回退
- 受管文件夹页面提供"回退到上一版本"，从本地快照恢复，最多保留 3 个版本。

## 网络与连接
- 组播被屏蔽（公司 Wi-Fi 客户端隔离）时，订阅页提供"手动输入 IP:端口"。
- 发布者离线时，订阅者显示"发布者不在线"，保留本地副本，不报错打扰。
- 首次运行时若被防火墙拦截，显示明确提示，并给出放行入站 TCP/UDP 53318 的步骤；安装包版由安装程序添加规则。
- 所有网络操作有超时；失败信息用中文说明原因（找不到设备 / 配对码错误 / 版本被拒 / 哈希不匹配 / 超时）。

## 数据库（schema 7 → 8）
- `published_config`：publishedId、名称、当前版本、哈希、创建时间。
- `paired_peer`：peerId、名称、证书指纹（pin）、配对时间、状态。
- `subscription`：subscriptionId、peerId、publishedId、本地版本、受管文件夹 ID、自动更新开关、跳过版本、最后检查时间。
- `config_snapshot`：subscriptionId、版本、快照路径、创建时间（保留最近 3 个）。
- 迁移测试：v7 库升级到 v8 数据不丢；无上述表的旧库可正常启动。

## 界面
- "共享"页签（现有隐藏的 LanShareTab 改为正式启用）：左侧 发布 / 订阅 两段切换。
- 发布：配置选择、发布新版本、自动发布开关、生成配对码、已配对同事列表（可移除）。
- 订阅：发现的发布者、配对、订阅列表（版本、状态、检查更新、回退、取消订阅）、手动 IP 输入。
- 所有确认框写清后果（"取消订阅将删除受管文件夹"）。

## 与现有功能的关系
- 复用：个人配置迁移包的格式与校验（清单、SHA-256、路径安全、导入预览）。
- 替代：历史页"发送到局域网"（LocalSend 协议）保持不变，不并入本功能。
- 不改：计算页、划词（已移除）、主剪切板历史。

## 限制与不做（第一期）
- 不做端到端加密之外的密钥管理；不做多设备账号体系。
- 不做分块续传、增量同步（每次整包）。
- 不做中转（发布者离线时不能由其他订阅者转发）——第二期。
- 不做公司共享文件夹来源——第三期。

## 验收
1. 单元测试：配对码 HMAC、指纹 pin、版本单调、哈希校验、路径穿越、高风险扩展名判定、链接校验、大小上限、schema 7→8 迁移。
2. 两台 Windows 实机（或一台 + 虚拟机）：配对成功/配对码错误/超时；发布 v1 → 订阅 → 发布 v2 → 提示 → 更新 → 回退；取消订阅删除受管文件夹；拔网线后订阅者显示离线。
3. 防火墙未放行时提示正确；组播屏蔽时手动 IP 可用。
4. 三套主题下的共享页渲染（LayoutCheck）。
5. 未实机验证的项不得写成"已验证"。
